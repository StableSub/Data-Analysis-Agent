Implementation Notes - Preprocess Routing and Plan Validation

Plan: .hermes/plans/2026-05-19_200138-preprocess-routing-validation-plan.md

Purpose: 구현 중 명세와 달라진 점, 해석이 필요한 지점, 설계 결정, 트레이드오프, 미결 질문을 실시간으로 기록한다.

설계 결정

2026-05-19: planner route 보정은 live LLM 테스트가 아니라 deterministic helper 테스트로 시작한다. 이유는 이 변경의 핵심이 LLM 품질 평가가 아니라 LLM 오판을 좁은 guard로 보정하는 regression contract이기 때문이다.
2026-05-19: 새 테스트 파일은 계획대로 backend/tests/test_planner_route_accuracy.py, backend/tests/test_preprocess_plan_contract.py, backend/tests/test_preprocess_workflow_error_handling.py를 사용한다. AGENTS에 언급된 planner guard 테스트 파일들은 현재 트리에 존재하지 않아 새 파일을 만든다.
2026-05-19: 루트 .gitignore가 backend/tests/*를 기본 ignore하고 일부 테스트만 예외 처리하고 있어, 이번에 추가한 root-level regression test 3개도 예외 목록에 추가했다. 테스트를 tracked artifact로 남기기 위한 변경이다.
2026-05-19: planner guard는 PlannerDecision을 복사하지 않고 같은 인스턴스의 preprocess_required만 수정해 반환하도록 구현했다. Pydantic 모델 복사를 추가하면 더 순수한 함수가 되지만, 현재 PlannerService.plan() 흐름에서는 직후 route 산정에만 사용되므로 최소 diff를 우선했다.
2026-05-19: ScaleOperation.method에는 기본값을 추가하지 않았다. 대신 schema test로 method 필수 계약을 유지하고, preprocess planner prompt에 standardize/normalize 필수 선택지를 명시했다. 이는 approval payload에서 실제 변환 방식이 드러나야 한다는 방향과 맞춘 결정이다.
2026-05-19: preprocess planning 실패 처리는 pydantic.ValidationError만 잡도록 제한했다. API 장애나 예기치 못한 runtime 오류까지 preprocess_failed로 삼키면 원인 분류가 흐려지므로 broad fallback은 추가하지 않았다.

편차

현재까지 의도적 편차 없음.
검증 명령 편차: 계획과 AGENTS에 언급된 backend/tests/test_main_workflow_analysis_happy_path.py, backend/tests/test_analysis_planning_accuracy_guards.py, backend/tests/test_planner_analysis_accuracy_guards.py는 현재 트리에 존재하지 않는다. 대신 새 deterministic tests, docs harness, evaluation workflow/runtime tests를 실행한다.

트레이드오프

route guard 범위: 완전한 intent classifier를 만들지 않고, 집계/시각화 키워드가 있으면서 명시적 전처리 키워드가 없는 경우만 보정한다. 정확도 개선 범위는 좁지만 기존 LLM 판단을 과도하게 덮어쓰지 않는다.
decision guard 적용 위치: LLM 응답 직후, route 산정 이전에 적용했다. route 산정 이후에 보정하면 PlanningResult의 preprocess_required와 handoff 플래그가 엇갈릴 수 있기 때문이다.
preprocess failure edge: planner node가 실패 payload를 반환하면 approval gate를 건너뛰는 conditional edge를 추가했다. 기존 executor 실패와 같은 preprocess_result.status="failed" 계약을 재사용해 main builder 변경을 피했다.
문서 갱신: workflow edge와 output type 설명이 바뀌므로 docs/architecture/orchestration/workflows.md, docs/architecture/backend-workflow.md, docs/architecture/shared-state.md를 최소 갱신했다. public API shape는 변경하지 않았다.

미결 질문

Reason 보호: 결측률이 높은 핵심 분석 컬럼(Reason)을 query-aware preprocess에서 보호하는 개선은 이번 hotfix 범위 밖으로 둘지, 후속 작업으로 별도 설계할지 확인이 필요하다.
